03 / How I work

  1. Principle 01

    Agents write the code. I own the decisions.

    An agent studies the ticket, records it in a knowledge wiki, and drafts a plan that I and a fresh agent review. The executor agent proves each change with tests it runs locally, such as characterization tests before a refactor. The merge request stays a draft until the reviewer agent and I have both checked it.

  2. Principle 02

    Pin down the old behavior before replacing it.

    Captured CheckProof's legacy scheduler in characterization tests, then moved customers' live schedules to the new system with a rollback switch that worked at any point.

    See the proof →
  3. Principle 03

    Make code safe to change, then change it.

    Upgraded Luce's Rails monolith from 7.0 to 7.2 by resolving transaction rollback, encryption, and dependency issues, with RSpec and VCR tests as the safety net.

    See the proof →
  4. Principle 04

    Code is cheap now. Proof isn't.
